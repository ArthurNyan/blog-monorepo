\begin{center}
{\Large \textbf{План демонстрации программного продукта}}\\[0.8em]
{\normalsize Тема ВКР: «Разработка системы управления контентом в сфере маркетинга на базе Strapi и Astro»}
\end{center}

\section*{Назначение демонстрации}

Цель демонстрации --- показать, что разработанная система:
\begin{itemize}
  \item реализует \texttt{CMS-first} подход;
  \item разделяет административный и публичный контуры;
  \item поддерживает локализацию, \texttt{preview} и базовый \texttt{SEO}-контур;
  \item использует воспроизводимую публикационную схему
  \texttt{publish -> webhook -> rebuild}.
\end{itemize}

\section*{Общий принцип демонстрации}

Полный развернутый сценарий с подробным показом всех сущностей, форм, ролей и live-проверкой
внешнего \texttt{rebuild} перегружает демонстрацию.

Оптимальное решение:
\begin{itemize}
  \item в основной live-демонстрации показать только ключевые пользовательские контуры;
  \item \texttt{rebuild} не запускать как отдельный долгий live-сценарий;
  \item вместо этого коротко показать, что webhook существует, подписан на
  \texttt{entry.publish} и \texttt{entry.unpublish}, и объяснить цепочку публикации.
\end{itemize}

Итог: систему лучше показывать в сокращенном и сфокусированном сценарии.

\section*{Что должно быть подготовлено заранее}

Перед выступлением нужно заранее проверить:
\begin{enumerate}
  \item frontend открыт и доступен по \texttt{http://localhost:4321};
  \item CMS открыта и доступна по \texttt{http://localhost:1337};
  \item заранее известна одна рабочая \texttt{page} для показа;
  \item заранее существует один draft для \texttt{preview};
  \item заранее открыты вкладки:
  \begin{itemize}
    \item \texttt{/ru/};
    \item \texttt{/en/};
    \item representative \texttt{page};
    \item \texttt{/vacancies/};
    \item admin panel \texttt{Strapi};
  \end{itemize}
  \item при необходимости заранее подготовлен раздел \texttt{Settings -> Webhooks}.
\end{enumerate}

\section*{Сокращенный сценарий демонстрации}

\subsection*{1. Введение}

Кратко проговорить:
\begin{itemize}
  \item тему ВКР;
  \item назначение системы;
  \item связку \texttt{Strapi} как контентного ядра и \texttt{Astro} как публичной витрины.
\end{itemize}

\subsection*{2. CMS-контур}

Показать в \texttt{Strapi}:
\begin{itemize}
  \item список ключевых сущностей;
  \item одну \texttt{page} или \texttt{home-page};
  \item \texttt{Dynamic Zone};
  \item \texttt{SEO}-поля;
  \item наличие draft/published состояния.
\end{itemize}

Что важно сказать:
\begin{itemize}
  \item контент редактируется в \texttt{CMS}, а не в коде;
  \item \texttt{editor} готовит черновик, а публикация отделена от редактирования.
\end{itemize}

\subsection*{3. Публичная витрина}

Открыть и быстро показать:
\begin{enumerate}
  \item \texttt{/ru/};
  \item \texttt{/en/};
  \item одну CMS-страницу, например \texttt{/ru/cms-first-platform/};
  \item при наличии времени --- одну статью, проект или страницу вакансии.
\end{enumerate}

Что важно сказать:
\begin{itemize}
  \item storefront-core работает в локалях \texttt{ru/en};
  \item страницы приходят из \texttt{Strapi};
  \item frontend использует \texttt{CMS} как источник контента.
\end{itemize}

\subsection*{4. Preview-сценарий}

Показать:
\begin{itemize}
  \item preview action в \texttt{Strapi};
  \item переход через \texttt{/api/preview};
  \item открытие \texttt{/preview/...}.
\end{itemize}

Что важно сказать:
\begin{itemize}
  \item draft не раскрывается через публичный API;
  \item preview использует \texttt{PREVIEW\_SECRET};
  \item preview-страница не индексируется.
\end{itemize}

\subsection*{5. Формы и прикладной контур}

Показать один безопасный сценарий:
\begin{itemize}
  \item публичную форму;
  \item обязательные поля;
  \item реакцию на невалидный ввод.
\end{itemize}

Если не хочется менять данные в системе, успешную отправку лучше не делать.

Что важно сказать:
\begin{itemize}
  \item формы идут через server-side route;
  \item браузер не пишет в \texttt{Strapi} напрямую.
\end{itemize}

\subsection*{6. Публикационный контур}

Показать коротко:
\begin{itemize}
  \item webhook в \texttt{Strapi};
  \item подписку на \texttt{entry.publish} и \texttt{entry.unpublish}.
\end{itemize}

Что важно сказать:
\begin{itemize}
  \item схема \texttt{publish -> webhook -> rebuild} реализована;
  \item live-показ внешнего \texttt{rebuild} нецелесообразен;
  \item для защиты достаточно показать сам контур и объяснить его роль.
\end{itemize}

\subsection*{7. Итог}

В завершении проговорить:
\begin{itemize}
  \item система реализует \texttt{CMS-first} подход для маркетингового сайта;
  \item контентный и публичный контуры разделены;
  \item реализованы локализация, \texttt{preview}, формы и публикационный контур;
  \item проект подтвержден не только кодом, но и воспроизводимыми сценариями проверки.
\end{itemize}

\section*{Что лучше не включать в основной показ}

Чтобы демонстрация оставалась управляемой, не стоит делать центральными шагами:
\begin{itemize}
  \item длинный переход по многим сущностям в \texttt{CMS};
  \item подробный разбор всех ролей;
  \item успешные мутации тестовых данных, если это не обязательно;
  \item live-показ внешнего \texttt{Dokploy rebuild/redeploy};
  \item попытку показать сразу все разделы \texttt{articles}, \texttt{projects},
  \texttt{vacancies} и формы.
\end{itemize}

\section*{Рекомендуемый приоритет показа}

Рекомендуемый порядок приоритета такой:
\begin{enumerate}
  \item \texttt{Strapi} page + \texttt{Dynamic Zone} + \texttt{SEO};
  \item \texttt{/ru/} и \texttt{/en/};
  \item \texttt{preview};
  \item webhook как доказательство публикационного контура;
  \item формы --- только если остается время.
\end{enumerate}

\section*{Вывод}

Показ и всего подробного плана, и отдельного live-сценария полного \texttt{rebuild}
перегружает демонстрацию.

Рациональный вариант для предзащиты:
\begin{itemize}
  \item оставить основной упор на \texttt{CMS}, витрину и \texttt{preview};
  \item \texttt{rebuild} показать как подтвержденный инфраструктурный контур, а не как
  длинную live-операцию;
  \item держать формы и дополнительные разделы как опциональный блок.
\end{itemize}
